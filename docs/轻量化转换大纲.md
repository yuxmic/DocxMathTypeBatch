# 轻量化转换大纲

本文件记录当前实现和目录约定。项目使用原生 C++、Win32、Word COM 和已安装 MathType API。

## 目录与入口

- `src/gui.cpp`：多文档队列、设置、界面显示和逐文档诊断。
- `src/gui_acceptance.h`、`src/gui_support.h`：独立的界面验收驱动，以及控件、队列记录和窗口辅助能力；验收模式继续通过原命令参数调用。
- `src/worker_client.cpp/.h`：后台进程、管道、任务状态和日志解析；GUI 通过该模块接收进度与结果。
- `src/agent_interface.h`、`src/app_version.h`：静态能力查询和程序版本；`assets/app.rc` 提供匹配的文件资源身份。
- `src/convert_docx.cpp`：命令参数、原件锁、任务副本、阶段调度、报告和结果发布。
- `src/body_conversion.cpp/.h`：正文正反向转换、坐标更新、恢复、保存重开及内容核验。
- `src/docx_scan.h`、`src/scan_file.h`：Word 范围、定界符和排除边界扫描，以及只读扫描文件入口；扫描选项由调用方显式传入。
- `src/latex_rules.h`、`src/app_error.h`：不依赖 Word 的文本兼容规则和失败断言。
- `src/docx_package.h`：DOCX 包、外链更新方式、嵌入资产和原生流核验，不管理 Word 实例。
- `src/equation_objects.h`、`src/equation_styles.h`：共用 OLE 插入、范围快照和正文公式样式准备。
- `src/omml_adapter.cpp/.h`：正文与其他区域共用的 OMML → MathML 适配，两个流程平行依赖此模块。
- `src/ultra_conversion.cpp/.h`：极速任务调度、资产缓存、DOCX 包写入及简单右编号，正式 GUI 和独立开发入口共用。
- `src/ultra_source.h`：极速正文四类公式的纯 XML 候选扫描、文本片段映射及倒序替换，不依赖 Word 范围。
- `src/ultra_assets.h`：极速的独立 OLE 工厂、已设字号的空存储模板、预览导出及厂商行内基线读取。
- `src/ultra_equation_worker.cpp`、`tests/try-ultra.ps1`：极速模式的开发入口；正式 GUI 无脚本运行依赖。
- `src/experimental_conversion.cpp/.h`：额外区域的选项、替换、恢复与保存核验，不依赖正文排版和编号模块。
- `src/layout_options.h`、`src/numbering_rules.h`、`src/native_numbering.h`、`src/body_numbering.h`：行距、编号格式、共用域识别规则、原生字段，以及本次编号的范围跟踪、引用更新和计数。
- `src/layout_warnings.h`：共用的只读尺寸判断和版式提醒记录，不改变转换计数或文档格式；正文和实验流程分别在已有核验阶段收集，任务发布后统一发送到界面。
- `src/worker_protocol.h`：工作进程和调用方共用的编码与进度协议。
- `src/conversion_timing.h`：任务内累计 XML、OMML 快照、XSLT、厂商导入、模板插入、对象激活、样式写入、编号创建/更新及 COM 成员解析耗时，任务结束时输出 `TIMING_DETAIL`；不增加逐式日志或线程。
- 实验区域按已提交的状态复用转换前快照；每式仍读取转换后状态并核验，恢复不推进缓存，整轮重置后重建。无失败时循环内状态读取由 `2N` 次降为 `N+R` 次（R 为实际处理区域数），最终保存核验保留。`EXPERIMENTAL_REGION_STATE` 统计完整状态读取，`EXPERIMENTAL_RECOVERY` 包含恢复阶段及其中的状态读取，二者耗时不能相加。
- `src/mathtype_api.h`、`src/word_automation.h`、`src/task_guard.h`：安装发现、厂商接口、独立 Word、取消与超时。
- `src/scan_docx.cpp`、`tests/native/`：开发命令行和原生互操作检查，不随用户 ZIP 分发。
- `skills/docx-latex-to-mathtype/`：随包携带 EXE 的 Skill、PowerShell 5.1+ 调用脚本及契约说明，按 `bin/DocxMathTypeBatch.exe` 相对路径运行，不依赖本机登记或源码目录。

构建入口为根目录 `build.ps1`，测试入口为 `test.ps1`，打包入口为 `package.ps1`。路径从脚本所在位置推导，不读取其他项目目录，不依赖当前终端目录。

源码继续放在扁平的 `src/` 中，按实际职责划分文件。常规模式由任务入口依次调用正文和实验阶段；快速模式在正文保存前转换额外区域，复用已打开的文档以保持仅保存一次。两者共用扫描、包资产、公式对象及 OMML 适配。正文设置、扫描选项和编号状态归属于当前任务，不由公共扫描头文件中的可变全局变量传递。

## 源码构建与测试

构建需要 PowerShell 7、MSVC x64 C++ 工具链和 Windows SDK，可通过 Visual Studio 或 Visual Studio Build Tools 安装。获取源码并构建 GUI，可在 PowerShell 7 中执行：

```powershell
git clone https://github.com/yuxmic/DocxMathTypeBatch.git
cd DocxMathTypeBatch
.\build.ps1 -Target Gui
.\build\bin\DocxMathTypeBatch.exe
```

Python 仅用于生成测试文档和检查 DOCX、PDF。开发测试需要安装依赖并构建全部开发工具：

```powershell
python -m pip install -r requirements-dev.txt
.\build.ps1 -Target All
.\test.ps1 -Suite Core -SkipBuild
```

| 分组 | 检查内容 |
| --- | --- |
| `Static` | 脚本语法、合成样本和提交内容检查，不启动 Office |
| `Pure` | 文本兼容、导出边界、编号格式、包资产和工作进程协议纯规则，不启动 Office |
| `Core` | 正反向转换、公式范围、布局、编号、高级设置、实验分支及独立 Skill 调用 |
| `Safety` | 取消、故障、超时、安装路径和外链保持 |
| `UI` | 界面、队列和诊断 |
| `All` | 依次运行 Core、Safety 和 UI |

所有非 `Static` 分组在 Office 专项前先执行原生纯逻辑检查；单独运行 `.\test.ps1 -Suite Pure` 只构建 `native-api-probe` 和 `worker-client-tests` 并执行这些规则，不启动 Office。文本和编号纯断言位于 `tests/native/native_api_probe.cpp`，生产转换入口不再附带重复断言。协议小样直接检查未知展示阶段、非法进度、逐式结果与最终摘要，以及取消后的清理失败，不启动后台任务。

专项结果的 `SourceSHA256` 由 `Get-TestSourceHashes` 读取 `upload-files.txt` 生成，键为项目相对路径。模块迁移后无需维护另一份固定源码列表；公开源码、测试辅助文件及构建脚本均纳入指纹。

运行全部回归使用 `.\test.ps1 -Suite All -SkipBuild`。测试使用生成的通用样本，结果写入 `tests/output/`。安全测试会对其创建并核实身份的任务进程注入故障，运行期间请勿手动操作测试窗口。

## 版本打包

项目采用 MIT 许可证，版权署名使用 GitHub 账号。构建结果位于 `build/bin/`。首版为 `v0.1`；当前 EXE 版本 `v0.1.5`，独立 Skill 版本 `v0.2.2`。程序版本在 `src/app_version.h` 定义，Skill 版本在其 `SKILL.md` 的 metadata 中定义。

执行 `.\package.ps1 -Target Exe` 生成 `dist/DocxMathTypeBatch-v0.1.5-win-x64.zip`。Skill 使用 `-Target Skill` 生成 `dist/docx-latex-to-mathtype-skill-v0.2.2.zip`，或用默认 `-Target All` 分别生成两包。程序包只包含 EXE、简要说明和 LICENSE；Skill 包使用单个 `docx-latex-to-mathtype/` 顶层目录，包含公开说明、脚本、元数据、LICENSE 和 `bin/DocxMathTypeBatch.exe`，不含用户配置或运行日志。分别通过 `-Version` 和 `-SkillVersion` 指定版本；版本必须与源声明一致。

GUI 构建后将 EXE 同步到 Skill 的 bin 目录，该目录作为生成物被 Git 忽略。源码上传清单包含文本、图标，以及经过检查的合成样本展示图和实测摘要；源码检出后先执行 GUI 构建。发布 Skill ZIP 直接注入 `build/bin/` 中已经验证的 EXE，不依赖 Skill 源码目录里的副本。单独打 Skill 包同样执行程序版本、构建哈希、依赖、大小和隐私检查，ZIP 回读逐文件 SHA-256，并在元数据中记录内置程序版本与哈希。

相同版本的输出不自动覆盖，打包不会自动运行转换测试。两个 ZIP 都回读文件清单和完整 SHA-256，确保只交付已检查的文件。

打包检查原生 x64、系统 DLL 白名单、无额外运行库及 EXE 不超过 2 MiB；不按某次构建的恰好大小限制后续必要功能。

GUI 必须通过 `/MANIFEST:EMBED` 将 Common-Controls 6 应用清单嵌入 EXE，不能依赖开发目录旁的 `.exe.manifest`。发布前执行 `tests/test-portable-startup.ps1`，将单个 EXE 复制到独立目录验证启动，避免遗漏开发目录中的隐含依赖。GUI 使用的 DPI API 要求 Windows 10 1703 及以上版本或 Windows 11 x64。

## 更新 GitHub 源码与网页发布

日常使用项目根目录的 `更新GitHub源码.cmd`：双击后自动调用 PowerShell 7，检查、提交并推送公开源码到 `yuxmic/DocxMathTypeBatch` 的 `main` 分支。需要本机已安装 Git、PowerShell 7，且 Git 可以登录该仓库；首次操作如出现 GitHub 登录页，按提示登录即可。窗口会保留检查结果，看到 `GITHUB_SOURCE_UPDATED` 表示成功；没有源码变化时直接结束。

首次使用可先在项目目录打开 PowerShell 7，只做本地预检：

```powershell

```

预检不联网、不生成提交、不推送，也不改变已有暂存区；远程状态使用本地缓存。实际更新会先获取远程状态。需要自定义提交说明时执行：


脚本只收集 `upload-files.txt` 中逐个列出的文件，并回读 Git 中准备上传的实际字节，再次检查绝对路径、本机身份、私人样本名称、常见密钥和非 GitHub 隐私邮箱。提交作者与提交者固定使用本仓库的公开账号及 GitHub 隐私邮箱。其他文件、其他分支、标签、私人文档和发布包不会随本次更新上传。移出清单的旧文件只取消 Git 跟踪，保留本机原文件。新增公开文件需同时加入 `upload-files.txt` 和 `.gitignore` 放行规则。

## Agent 调用接口

`--describe --json` 和 `--help` 在 COM、GUI、Word 和 MathType 初始化之前返回。能力查询声明应用身份、程序版本、`CliContractVersion: 1`、报告版本、支持方向、正文 OMML 默认行为和四类实验区域。未知公共命令返回 JSON 错误与退出码 2，不弹模态窗口。转换报告额外包含应用版本和接口版本，原有 `SchemaVersion: 1` 与字段语义保留。

Skill v0.2.2 按相对于脚本目录的 `../bin/DocxMathTypeBatch.exe` 调用配套程序，不读取旧版 `AgentExecutable` 登记，也不自动搜索或下载外部程序。GUI 启动不再登记路径，既有 PointSize 设置保持。包内程序缺失时明确提示重新解压完整包。`connect.ps1` 仅作可选的包内身份和协议诊断，不接受外部程序路径；转换脚本直接验证并使用包内 EXE，整个 Skill 调用不启动 GUI。产品身份及有界协议检查保留，防止错误产品或不兼容包阻塞调用。

Skill 通过现有受监管 worker 转换，使用全新任务目录、Windows 参数引用和 UTF-8 JSON Lines。默认本机用户数据目录可通过脚本 TaskDirectory 参数改到明确目录；完整报告和原始日志保留在本机，默认终端摘要只含状态、计数、问题与路径。任务启动即给出停止标记；中断只请求本任务清理。PowerShell 脚本以带 BOM 的 UTF-8 保存，兼容 Windows PowerShell 5.1 对中文脚本的读取；后台日志异步写入文件，任务返回值显式丢弃，保证 stdout 仅为 JSON。

Skill 的机器摘要与 GUI 中文摘要独立。成功公式只计数，`PreservedItems` / `Issues` 保留状态、原因、可用位置和短片段，`Warnings` 单独报告尺寸风险。`VerificationMode` 区分标准核验、快速未核验和极速未核验。极速包装脚本使用 `-UltraConversion` 和固定字号，通过能力查询确认包内 EXE 支持 `Ultra`，并按极速报告契约标注结果。

`tests/test-agent.ps1 -SkipBuild` 从中文、空格路径下的完整 Skill 副本验证 PowerShell 5.1/7 的包内调用、忽略旧绑定、整包移动、缺失 EXE、错误产品、不兼容协议、查询超时、正反向、部分完成、覆盖保护、BUSY 及实际替换后的安全取消。测试用本机登记与字号有快照，结束后恢复，不把用户配置写入分发包。

## 构建偏好

偏好使用mathtype原生功能，使用精简的代码逻辑，在保证稳定的前提下以提高转换速度为目标。

三档模式按执行方式和交付要求区分，不按公式数量硬设门槛。正式程序提供标准／快速／极速三级滑块；正文行内／行外的 LaTeX 与 OMML 是三档共同的基本范围。极速只保留该范围的转换、指定字号及简单右编号，其余位置和附加功能不进入执行路径。

| 模式 | 基本理念 | 失败行为与核验 |
| --- | --- | --- |
| 标准（当前常规模式，默认） | 完整功能、完整核验和失败恢复，面向正式交付。通过批量读取、缓存和减少 COM 往返提速，保留逐式检查、阶段恢复、保存重开及包内容核验。 | 单式失败恢复并核验；需要时重建副本。结果只报告实际完成的检查，不宣称数学等价。 |
| 快速 | 通用高效转换，保留现有完整功能和局部失败后尽量完成其他公式的能力。跳过完整核验，不为形成中间档重新加入逐式复查、检查点和保存重开。 | 单式失败尽量局部撤回后继续，不完整核验恢复结果；最后保存一次，输出明确标记未经核验。 |
| 极速 | 大批量吞吐量优先。直接解析正文普通段落中的行内／行外 LaTeX 和 OMML，在文档外生成独立可编辑公式、预览及尺寸，统一指定字号，按需直接写入简单原生右编号。运行时不启动 Word。 | 不做结果核验、逐式回滚、恢复重试、兼容性补救或自动降级。单式生成失败保留原节点并继续；服务或输出写入故障终止任务。 |

极速的速度来自减少工作量：源内容一次解析，编号显示值在内存计算并连同原生域结构写入，避免逐式 `Field.Update`。行内和行外的字号样式分别只写入一次空模板，逐式复制存储并加载独立对象；相同内容、来源及行内／行外类型复用生成资产，每个出现位置仍写入独立嵌入部件。运行时取消验证性工作，开发时用小型定向样本确认生成规则。并发只用于可独立的工作；本机双进程 MathType 试验已发生 RPC 断连，当前保持单进程，不把共享单例服务简单包装成多线程。

原件另存、不覆盖既有输出、取消及任务资源归属属于共用文件与任务管理。标准和快速继续拒绝开启修订或限制编辑的输入，判断复用扫描的 `tracksChanges` 与 `protectedDocument`。极速不得通过关闭保护或执行外部内容来换取速度。

GUI 的“转换模式”为三档离散滑块：标准／快速／极速；默认标准，运行期间固定当前模式，支持键盘方向键和焦点提示。GUI 与工作进程状态共用 `ConversionMode` 枚举，报告记录同名字段；旧快速参数仍映射快速档，极速使用 `--ultra`。极速固定选择“所有正文”和“指定字号”，向 worker 传递 `--scope=all`，保留字号输入和行外右编号；禁用其他位置、行距及复杂编号。切回后恢复原范围及字号方式，切到反向时回到标准档。

只读扫描中的集合数量在进入本次循环时读取一次，编辑后重新扫描时重新获取，不跨编辑缓存范围或集合。收尾日志用 `WORD_QUIT_MS`、`WORD_COM_RELEASE_MS`、`COM_UNINITIALIZE_MS`、`TASK_WORD_EXIT_MS`、`TASK_FILES_CLEANUP_MS` 区分退出、代理释放和文件清理耗时；计时只读时钟，不增加等待或后台线程。

普通和快速转换共用 `UI_PHASE` 与 `UI_STAGE_PROGRESS` 展示实际执行的步骤，正反向及已启用的额外区域均覆盖。段落、公式、对象、文档部件、文件块、报告条目、交付文件及临时文件清理显示真实计数；文件复制使用系统回调的实际字节比例。单次 Word/MathType 接口、保存、包序列化、代理释放和进程退出等无法取得内部百分比的调用，先显示具体动作，再等待调用返回。单式内部动作保留公式总体进度；计数达到总数只表示该步骤完成，报告生成、交付及退出清理继续显示各自阶段。GUI 每秒更新本步与总用时，同一阶段的计数变化不重置本步时间；快速模式跳过的核验不出现在进度中。取消后仍展示释放与清理，不能借此重新接受转换统计或交付结果。

快速模式在文档完成保存、关闭，Word 的 Quit 返回且 MathType 接口正常结束后，才通过共享状态的 `wordQuitComplete` 通知监管进程完成本任务 Word 的收尾。此处复用原有 PID、创建时间和进程映像核对及有界退出流程，将既有收尾提前到 COM 代理析构前，避免代理等待已在退出中的 Word。工作进程仍正常析构、清理与提交，不跳过资源释放；取消优先级和输出身份核对保持。普通模式仍在工作进程结束后完成同一收尾。

## 转换范围

默认正向，反向维护基本导出。正向支持全部、仅行内和仅行外；默认跟随原文字号和行距，不添加编号。字体采用 MathType Times+Symbol 基线，不修改全局偏好。

基本流程默认同时处理正文 LaTeX 与 OMML；任务级 `ScanOptions.convertOmml` 默认 true，高级设置可关闭，worker 参数为 `--skip-omml`，同时作用于正文及已启用的额外位置。关闭只禁止 OMML 成为转换候选，不移除其排除边界或常规保留核验，不将主动保留计作拒绝或部分完成。反向始终保留 OMML。实验项关闭时表格、文本框、页眉页脚和脚注尾注保持。保护、修订、普通域、OMML、已有 OLE 和内容控件构成 LaTeX 词法识别边界，安全范围内的正文 OMML 作为另一种来源进入同一清单。已有独立行外 MathType 可以进入布局和编号计划，原生公式数据保持。界面范围为“所有正文／仅行内／仅行外”，后两项也约束启用的实验目标。

识别 `$...$`、`$$...$$`、`\(...\)`、`\[...\]` 和整段缺失左反斜杠的 `[...\]`。独占段落判为行外，夹在正文中判为行内；不识别裸公式。

正文逐段预筛选后使用 Word Find 定位，禁止直接把字符串索引当作 Word Range 坐标。结构化公式可跨段或软换行；普通货币、破损环境及后续公式起点不会被吞并。原始 Range 保留用于核对和恢复，提交 MathType 的副本合并 Word 源码换行，保留 TeX 双反斜杠。

`compatibleTex` 只修改导入副本，正文和实验区域共用。`aligned`、`align*`、`split`、`alignedat`、`alignat*` 按实际顶层分列转换为 `array`，`gathered`、`gather*` 使用居中列，`subarray` 保留原有列格式参数。命令改写覆盖粗体、正体文字、直立数学字母、绝对值分隔符、可伸缩括号、部分点号和定义等号；完整列表与实测依据见 `MathType兼容LaTeX书写规范.md`。匹配完整控制序列，保护转义和文字参数，保留多组等式、嵌套结构和源码换行。未知命令继续使用 MathType 的部分解析结果，不新增未解析命令检查或因此回滚；不增加长公式自动拆分或缩放。

## 实验性功能的边界

`--experimental-fast` 是独立于四类额外位置的快速模式；首页三级滑块选择快速档，仅在当前会话生效，重启或恢复默认回到标准。正文与已启用的额外位置共用此模式。输入仅建立排版所需的样式信息，跳过内容/资产基线、正文片段快照、可选语法预检和逐式复查；不建立阶段检查点，不因单式恢复无法核验而重建整份任务。公式定位、范围边界、必要参数、原件只读锁、不覆盖输出、取消和任务进程归属仍保留。

快速模式在同一个打开的 Word 副本内依次转换正文与额外位置，最后保存一次；没有保存前全文核验、保存后重开/重扫或包资产核验。单式失败尽量撤回并继续，记录 `FAILED_UNVERIFIED`，不承诺原式已完整恢复。报告增加 `FastConversion`、`FailedUnverified`，将 `Validation` 设为 `SKIPPED_EXPERIMENTAL_FAST`、`PostConversionScans` 设为 0、`WordReopenVerified` 设为 false，未经执行的字节和资产核验字段为 null；位置标识为 `WORD_WORKING_COPY_UNVERIFIED`。快速模式不执行原文分页和逐式页码查询，正文保留原始段号、字符坐标，额外区域仍冻结区域键及原始相对坐标供结果匹配。普通模式保留原有核验及字段语义。

快速模式的页眉页脚引用从始终持有只读锁的原件读取，公式替换仍操作已打开的工作副本。不能用 OPC 接口重新打开正被 Word 编辑的工作副本，否则会报 `Read stored header references 0x80070020`，并跳过整批实验区域。`tests/test-experimental-fast.ps1` 覆盖四类位置全开的快速正向、快速反向及普通正向转换，并独立核对输出包。

能力查询增加 `ExperimentalFastConversion: true`；Skill 的 `-FastConversion` 只在明确请求此模式时传递，包装脚本检查模式一致性并如实输出 null/false 核验字段，不再把快速结果标为已核验。文件队列和详情分别显示“快速”和“未核验”。快速模式通过任务与扫描选项显式传递；原生纯逻辑用例覆盖同一文本在常规和快速参数下的语法判定，轻量回归覆盖快速正向/反向、编号及单式失败仍能保存输出。

本机一次集中验收使用含 LaTeX、OMML、表格、空白内容控件及普通域的 11 式合成样本：相同设置下默认模式约 12.17 秒，快速模式约 5.21 秒。实际 GUI 完成快速正向及 6 个编号，快速反向导出 11 式；单式故障后保存其他 10 式，失败项标记未经核验。另验证 PowerShell 5.1 的 Skill 包装不会把快速输出误报为已核验。此为有限样本功能和计时对照，快速模式不承诺内容正确。

基本方向仍为 LaTeX → MathType、MathType → LaTeX。OMML 转换开关位于高级设置右侧“转换内容”，默认勾选，与下方默认关闭的实验位置分开；点击确定后保存当前会话选择，取消不提交，正向恢复默认重新勾选。反向时禁用 OMML 开关，保留此前正向选择。`ExperimentalOptions` 仅保存表格、文本框、页眉页脚、脚注尾注四项选择，不写入用户注册表。高级设置左侧为基本设置；反向时禁用左侧正文格式设置。小工作区或高 DPI 时滚动整个设置窗口，焦点进入隐藏控件时自动滚到可见位置。能力查询新增 `OptionalOmmlConversion: true`，报告新增有效设置 `ConvertOmml`，原默认行为及 CLI/报告版本保持兼容；Skill 使用 `-SkipOmml` 请求关闭。

OMML 开关专项已通过：`test-advanced.ps1 -SkipBuild -Case Omml` 的默认开启、常规关闭、快速关闭、反向保留和仅 OMML 无目标五项；`test-batch.ps1 -SkipBuild -PreviewOnly` 检查默认勾选、保存、取消、恢复默认、反向禁用以及真实工作进程传参，并完成截图检查。另完成一次 Windows PowerShell 5.1 的 `-SkipOmml` 调用，报告零目标、无拒绝、常规保存重开通过。未运行全量套件或重新测量转换性能。

工作参数保留 `--experimental-tables`、`--experimental-textboxes`、`--experimental-headers`、`--experimental-notes`，不再有 OMML 开关。额外位置正向处理 LaTeX 与 OMML、反向导出 MathType。表格和文本框属于正文及已启用其他区域的子容器，不自动开启其父区域。

正文扫描复用已有 `OMaths.Count`：没有 OMML 时跳过目标构造、XML 快照和 Office XSL 加载；存在时仅把安全正文范围内的 OMML 并入现有目标清单。LaTeX 和 OMML 共用倒序转换、字号、行距及行外布局，之后按正文顺序一次性给成功的新旧行外 MathType 编号。未成功转换的 OMML 按原序逐式核对内容。此路径复用原有保存重开，不为 OMML 增加第二轮 Word 打开。

独立正文 OMML 后只有空白及括号内数字编号时，将整段安全内容作为转换目标，清掉旧手动编号及空白，并按行外布局居中；Word 原始类型为行内也按此上下文归类，随后才应用行内/行外筛选。编号识别支持中英文括号、纯数字及带点或连字符的章序号；正文、单位、其他公式及域/控件边界不纳入清理。上下文复用本轮已读段落文本；段落序号从已记录的 Word 段落起点二分查找，不逐式读取文首至公式的 Paragraphs.Count。文本查找只判断上下文，实际替换坐标来自 Word 范围。`test_input_forms.py manual-omml-fixture/manual-omml-check` 覆盖常规、快速及重新编号三种设置。

LaTeX 的四种定界符复用同一个 `manualEquationNumber` 判定；只有整段公式和尾部编号均落在扫描传入的安全片段 `allowed` 内时，才把编号纳入替换范围。公式原始 `inner` 仍只包含 TeX 内容，旧编号不送入 MathType。`manual-latex-fixture/manual-latex-check` 覆盖常规、快速、重新编号，以及正文、单位、域和控件反例。

开启额外位置后，先在只读文档上检查启用区域是否存在可转换候选：正向没有 LaTeX 定界符文本与 OMML、反向没有 Equation.DSMT 对象时，实验阶段直接复用正文核验结果，不打开 Word 实验副本、不保存重开，报告记为 `NO_TARGETS`。存在候选时，在首次实际写入前为已经完成正文转换和核验的副本保存一个私有检查点（惰性创建），再执行实验分支，独立保存重开、核对区域内容与原生资产，最后统一交付；实验阶段若没有任何成功替换（全部拒绝或失败且恢复核验通过），同样跳过保存重开，报告记为 `NO_CHANGES`。实验阶段复用正文核验已经批量读取的原生流与媒体清单，不再次整包读取。正文表格按顶层表格分别处理，嵌套表格归属于其所在顶层表格。其他位置保持各自范围，链接文本框仍按完整文本链去重。逻辑对象计数复用已选区域清单，正文表格不重复计数，也不为关闭的实验项枚举 COM 区域；包内保留原生流及媒体仍全量核验。

实验分支仅处理额外位置并替换公式，不调用字号偏好、正文 `DisplayLayout`、段落行距或右编号处理。正文 OMML 不在此分支，避免失败原式被再次尝试。已有 LaTeX 的反向定界符归一仍只在基本流程执行，额外位置的反向分支只导出 MathType。

识别复用同一 LaTeX 词法器；`ScanRangeContext` 的基本正文路径继续使用 `Document.Range`，额外区域通过所属 Range 创建子范围。每个区域重扫后倒序处理，单元格结束标记、普通域、修订和内容控件保持为边界。链接文本框通过整个文本链范围去重；页眉页脚按实际节引用访问，继承前节的区域不重复处理。

OMML 由 Office 安装目录中的 `OMML2MML.XSL` 转为 MathML，再通过厂商语言类型 2 导入新建 MathType 对象。转换资源按任务首次需要时加载，不复制 Office 文件进项目。缺失资源或导入失败保留原式。

正文 OMML 在替换前保存所选范围的原生 XML。Word 的结构化公式编辑会结束自定义 Undo 记录，失败时使用这份 XML 恢复当前替换范围，再核对原式 XML、文档全文、格式、长度和对象数；不连续调用 Undo 猜测步数。行外 OMML 先替换为 OLE，再在公式区域外添加前后 Tab，避免向原生公式内部写入制表符。LaTeX 保持原有 Undo 恢复路径。

每条替换独立恢复并核对周围文字与容器段落属性；正文及实验区 OMML 使用原生 XML，其余可撤销编辑沿用 Undo。恢复无法确认时，由调度重建正文副本或回退实验检查点，跳过问题范围，禁止继续使用恢复状态不明的文档。保存前重新核对逐式位置绑定，保存重开后逐区域核对文字、段落与表格属性、普通域、剩余 OMML，以及有序 MTEF；再核对全部逻辑 MathType 对象的数量和完整内容。包检查核对保留的原生流与媒体，新序列化内容只允许来自原对象、新导入数据或已核实的空模板。报告的 `Experimental` 包含实际选项、逐式位置类别、成功及保留数量，`FormattingApplied` 固定为 false，`Skipped` 为空字符串表示正常执行，`NO_TARGETS`／`NO_CHANGES` 表示实验阶段未保存重开；顶层计数包含基本与实验目标。

实验阶段保留 `UI_EXPERIMENTAL_PHASE PREPARING` → `CONVERTING` → `VERIFYING` 的阶段标记，并为区域枚举、候选扫描、位置采集、逐式转换、内容核验、保存重开及区域恢复补充具体步骤与计数。保存重开核验通过后输出 `EXPERIMENTAL_CONVERSION_VERIFIED`；短路路径输出 `UI_EXPERIMENTAL_SKIPPED NO_TARGETS` 或 `NO_CHANGES`，不输出未实际执行的转换、核验与完成标记。展示事件不改变逐式结果。

维护时注意：Word 表格行末段落可能报告在表格内，但 `Cells.Count` 为 0；区域选择按实际表格范围判断，不能只依赖公式 Range 的 `Information`。前一脚注的修改会移动后一脚注坐标，表格边界在各区域扫描前刷新。保存时可重新分配文本框 `Shape.ID`、页眉部件名和 `rsid`，定位与核验不能依赖这些元数据。MathType 导入会向对象写入内容，每条公式必须新建空对象，不能通过向旧对象导入空 MTEF 代替清空。Office 的 OMML 模板输出 MathML 片段，导入前需补齐 `math` 根元素。

DrawingML/VML 兼容表示及链接区域可能包含重复或空的 OLE 部件，物理部件数不能作为逻辑公式数量。独立测试读取当前 Word 生成文档的有效兼容分支，避免把备份重复计数；生产核验以 Word 的实际对象、逐式绑定和逻辑内容计数为准，保留的缓存部件也需匹配已知原生数据。

页眉页脚区域清单从 DOCX 的 `/word/document.xml` 读取实际保存的当前节引用，排除 `sectPrChange` 中的历史节属性；正式转换在打开可写副本前读取，存在性预检在正文已核验的只读副本上读取同一来源。`Range.WordOpenXML` 可能额外导出未持久化的空槽位，`HeaderFooter.Exists` 也会漏掉已保存但当前未显示的首页或偶数页页眉页脚，不能用它替代保存的引用。预检、转换和保存重开使用相同的节与类型定位规则，保存后按区域键匹配，保留逐区域文字、版式、字段与原生内容核验。

实验分支中只有正文表格会移动主故事坐标。正文报告的 `FinalStart` / `FinalEnd` 在所有实验修改保存重开核验通过后，按各顶层表格实际末端的累计偏移修正；嵌套表格归入父表格，不重复叠加偏移。无修改或实验结果全部回退到正文检查点时保持原坐标。位置修正不额外打开 Word 或重扫正文；`tests/test-experimental.ps1 -Case review -SkipBuild` 使用表格前、表格之间和表格后的合成公式，独立重扫最终输出，覆盖正反向、部分保留和区域回退。

## 布局和编号

行外使用 `MTDisplayEquation` 样式和“Tab＋公式＋Tab”，通过中心和右制表位定位。清理首行缩进，保留段前段后、左右缩进；高级行距只在显式设置时写入。

可选编号按文档顺序覆盖新旧行外公式：无号补号、有号更新，保留原编号书签并更新相关 REF。编号采用 MathType 原生 `MTPlaceRef` 嵌套域，支持章、节、序号、括号、分隔符和指定起始值；不扫描标题、不自动分章。

编号会话拥有本次计数和核验范围，以内存中的 Word Range 跟踪修改，在已有普通域核验循环中收集逻辑域序号，关闭文档前仅固化该序号快照，不再为冻结范围重新遍历全部域。保存重开改变域代码长度时仍按逻辑域顺序核验。程序不再建立内部 `DMTBNum_` 书签，用户已有引用书签保持。原生编号专项保留交付文件不增加内部书签的检查。

显式起始值通过同段隐藏序列种子保持，默认路径不新增该种子。不创建公式章节断点、章节字符样式或红色说明，不修改共享 NEXT_EQN 偏好。

末段公式或已有编号范围可能正好覆盖 `Document.Content.End`。该排他末端不能用于创建折叠 `Range`；独立正文快照的尾片段为空时直接保存空字符串，不要求文档以普通文字段落结束。

## 恢复与核验

非复合存储的嵌入部件（例如图表的 XLSX 工作簿）不作为 MathType 解析；正常公式继续处理，正文及实验阶段均核对这些部件的原始字节保持。反向归一定界符分别使用起止长度，兼容 `[...\]`；`\%` 作为文字百分号保留，两个方向的未转义 TeX 注释均拒绝。原生导出若带有嵌套的 `$`、`\[\]` 或 `\(\)`，在替换前保留当前对象，避免整份文档在重扫时失败。

正文反向核验分别检查逻辑对象数和物理资产：同一 OLE 或预览部件可被多个对象引用，不按成功对象数强制扣减物理部件数；所有保存后的原生流和媒体仍须逐字节来自原包，未导出的资产继续核对保留数量。`test_input_forms.py shared-fixture/shared-check` 覆盖共享对象全部导出，以及表格仍引用共享资产的情况。

逐式核对源范围和原生内容。LaTeX 和已有对象的可撤销编辑失败时使用 Undo；正文和实验区 OMML 使用原始原生 XML 恢复，并核对段落边界、内容和版式。准备步骤尚未写入目标时可直接保留原式。已有正文公式排版也有独立恢复与原生数据核验。

生产反向转换复用调度层已经核对过的正文片段快照：成功路径检查目标文字和对象数量，失败恢复时才读取整篇正文，与当前已成功结果共同构造的预期正文比较；保存前及保存重开后的全文、普通域、OMML 和资产核验照常执行。开发自检保留逐式前后全文检查。`test-lightweight.ps1` 的 `reverse-snapshot-recovery` 在后方公式已导出后注入失败，检验重建与保留结果。

正文和实验区域的单式 OMML 只读取一次 `WordOpenXML`，签名、恢复及 MathML 导入共用该原始字符串；导入仅修改另行解析的 DOM，恢复所用 XML 保持原样。`requireContains` 按字节内容建立引用多重集，保留重复资产计数而不复制整份媒体数据；包媒体读取后直接移动到资产清单。原生小样同时检查重复资产缺失仍被拒绝。

正向正文保留核验在超过三个 OMML 且正文没有内嵌/浮动对象时，尝试一次导出正文 XML，只抽取 `/word/document.xml` 主故事中的公式，包含正文表格、排除文本框；公式涉及兼容分支或修订时沿用逐式读取。批量清单须与 Word 实际公式数量一致，并与首尾两式的逐式完整 XML 对齐。Word 的 `Range.Text` 含结构分隔和数学字母映射，不能用 `m:t` 拼接结果直接比对。混合图片/OLE 文档、小清单和对齐失败继续使用原逐式路径，避免整包资产导出的开销。

OMML 适配按现有正文/实验阶段生命周期缓存编译后的 `IXSLTemplate`，以 `FreeThreadedDOMDocument60` 加载 Office 样式表，每式创建独立 processor 并传入选中的 `oMath` 节点。保留禁 DTD、禁外部解析和原始恢复 XML；已解码 MathML 文本全为 ASCII 时跳过顶饰修复，去空白后仅写回实际变化的节点。只读扫描内复用 OMML 对象、范围和真实坐标，函数返回时释放缓存；仅跟随原文字号时读取字号，保存后重扫不读取字号。行内替换跳过仅用于行外拆段的段落访问。

`TIMING_DETAIL` 的 `SOURCE_XML` 包含源 XML 获取和签名准备，`OMML_SNAPSHOT` 单列保留核验快照，`XSL_COMPILE` 包含首次样式加载和编译；`SOURCE_LOCATIONS` 单列原文分页、正文及已启用实验区域的定位采集，其他记录 XML 准备、XSLT 变换、MathML 适配、TeX/MathML 厂商导入。新增 `TEMPLATE_INSERT`、`OBJECT_ACTIVATE`、`STYLE_WRITE` 分别记录模板插入、正文对象激活和样式写入，`NUMBER_CREATE`、`NUMBER_UPDATE`、`NUMBER_RESULT` 分列编号结构创建、子域更新与结果读取；`COM_RESOLVE` 累计 `GetIDsOfNames`。计数包含失败尝试，COM 解析与上层计时嵌套，这些值不能直接相加或与总耗时重复相加。

极速路径进一步拆分 `OLE_CREATE`（新建空对象）、`OLE_LOAD`（复制已设样式的空存储并加载）、`OBJECT_ACTIVATE`（设置宿主、激活及取得接口）和 `OLE_CLOSE`（关闭对象）。这四项分别计时，便于区分模板准备、每式加载与实际激活成本。前版极速的 `OBJECT_ACTIVATE` 包含创建与激活，不能仅凭新旧同名计时减少就认定整条对象路径提速。

2026-10-29 的合成样本对照：400 段正文、20 个 MathType 公式的反向正文转换，两组交叉计时平均由 3.36 秒降至 2.66 秒；含 18 个 OMML、共 25 个公式的正文/表格混合样本，正文转换由 6.41 秒降至 4.06 秒，单次任务总耗时由 16.23 秒降至 13.67 秒。反向任务总耗时基线为 10.91/13.14 秒，优化后为 12.83/13.00 秒，交付后的退出与清理存在约 2.2 秒波动，尚不据此认定反向整任务提速。报告、正文、表格、原生公式字节及已有媒体保持一致；生产反向恢复和 OMML 原始 XML 恢复各注入一次故障，均保留失败原式并交付其他公式。以上为本机有限样本对照，不是全量压力测试。

行外公式向段首、段尾扩展外侧空白时，仍须受原扫描片段和排除范围限制。空结果域和仅含空格的内容控件在可见文字中可能无法区分，不能仅凭整段看似空白就把它们纳入替换；LaTeX 与正文 OMML 共用这一边界要求。`ContentControl.Range` 只覆盖内部内容，首尾的不可见控件标记也必须排除。含内容控件的表格在整段与切片的 `Range.Text` 中可能返回不同的结束标记，实验阶段按相同范围分别核对替换前后的前片段、后片段及目标内容，不拼接切片推断整段文字。`test_input_forms.py boundary-fixture/boundary-check` 覆盖前后相邻的普通域、内容控件、正文表格和普通跨段公式。

正文单式恢复无法确认时，关闭并丢弃当前副本，从一直持有只读锁的原件重建，跳过该式后重做其他正文目标；正常路径不为每条公式创建磁盘备份。实验区域失败时从已核验的正文检查点恢复，跳过失败区域后重做其他区域；同一范围不反复尝试。若无法确认区域边界或保留区域本身仍不能通过核验，则仅交付已核验的正文副本，明确其余实验项未完成。不能通过捕获异常继续使用恢复状态不明的文档。

右编号包含序列、起始值及 REF，整个阶段一起成功或回退。仅在开启编号并有适用目标时建立编号检查点，失败恢复本次编号及引用修改，保留此前转换和排版结果，恢复副本仍需完整核验。

报告沿用 `COMPLETE` / `PARTIAL`，退出码 0 表示交付了有效文档，不代表目标全部成功。`Issues` 单独记录区域、排版、编号等问题，实验问题同时写入 `Experimental.Issues`；已知跳过目标计入 `NotAttempted`，扫描失败而数量未知时只记录区域问题，不编造公式数量。任一失败、拒绝、跳过或问题都会使文件显示“部分完成”。重建副本时 UI 清除已撤回尝试的中间计数与详情，最终摘要只反映实际交付内容。取消、全局偏好异常及无法继续核验的整文件故障仍终止任务。

`tests/test-experimental.ps1 -Case failures -SkipBuild` 使用合成的两张表格、文本框、页眉页脚和注释，分别注入扫描、替换、恢复、保存后校验及编号故障，检查正反向保留内容、其余区域输出、原件字节、文件行“部分完成”和清理。故障变量仅由测试子进程继承，不读取私人样本。

正文和实验区日志共用 `diagnosticExcerpt`，按完整 UTF-16 字符截断摘要。原生公式的数学字母可能使用代理对，直接 `substr(0,160)` 后编码会误报 `UTF-8 length` 并跳过正常区域；`-Case long` 使用命中该截断边界的长公式回归，日志不能改变转换结果。

人读诊断与技术日志分开：`WorkerState` 保存结构化问题，队列在任务清理后继续持有它们；详情默认显示页码/区域、原式片段、中文原因及修改建议，按钮切换原始日志，不从英文日志反解析位置。`SourcePosition` 在任何替换前冻结真实公式起点和连续物理页，正文恢复重建复用初始定位。启用实验区域时预采集原文位置，正式转换按区域、原始顺序、类型及相对位置关联，不按相同源码字符串猜测。正文/表格使用公式起始页；页眉页脚明确共用，脚注尾注注明引用页，串联文本框不能把首框页码套给全部公式。页码是当前电脑 Word 对原文的排版结果，包含封面且忽略页脚分节起号；位置不可得时标记未知。一次原文分页有实际开销，通过 `SOURCE_LOCATIONS` 留档，不在每式重复分页。报告新增 `SourceLocation` 和 `Page`（未知为 null），保留原有 `SchemaVersion: 1`。

页码日志专项已通过 `test-diagnostics.ps1 -SkipBuild -Case Pages,Invalid`：同一坏公式在正文、两张表格及两节页眉分别定位，核对原件字节、摘要/原始日志切换、当前视图复制和任务清理。72pt 重排使第二页标记实际移至输出第三页，摘要仍记录原文第二页；原文第三页在第二节显示页码为 1，日志仍使用连续页序 3。独立 `native-api-probe --diagnostic-pages` 只读核对这两种页码及真实分页变化。两个合成场景的 `SOURCE_LOCATIONS` 为 343/347 ms，各仅采集一次；不据此推算其他文档耗时。协议纯回归覆盖未知页、拒绝、普通/快速失败、中断上下文、恢复撤回及问题重放，未执行全量套件或压力测试。

保存后只读重开并重扫，关联对象位置、关系和完整 MTEF；核对新增公式、原有流、媒体、普通域及表格结构。交换两条不同公式必须被拒绝，数量相同不构成通过依据。原件持有只读锁并在交付前核对完整字节。

取消停止剩余队列并丢弃当前未交付结果，保留此前成功输出。只管理经过 PID 和创建时间核实的任务 Word，禁止全局结束 Word 或 MathType。

任务 Word 创建时即加入专属 Job，以系统启动隐藏、按 PID 获取的原生对象及 `Application.Visible=false` 控制可见性，不释放或注入窗口守卫 DLL。通过 `/w` 启动独立空白文档提供原生对象，不再通过命令行打开启动 RTF，避免 Word 再次显示文档窗口。任务期间使用线程执行状态阻止空闲自动睡眠，允许熄屏与锁屏；退出及嵌套恢复结束时还原该线程原有请求。心跳、Word 启动及结果提交超时统一使用 `QueryUnbiasedInterruptTime`，不计入主动睡眠、休眠时间。`native-api-probe --task-power-self-test` 检查线程电源请求的正常/异常释放、嵌套恢复及心跳时钟。`test-ui-experience.ps1` 和 `-Reverse` 覆盖正反向的窗口显示、前台占用与清理；SHOW 通知即使在回调时窗口已隐藏也保留，隐藏窗口的激活通知另存原始日志，不将其直接当作窗口已显示。

前台保护由 `task_guard.h` 的监管父进程执行：通过进程外 `EVENT_SYSTEM_FOREGROUND` 通知和现有任务循环的消息等待跟踪最近非任务前台窗口。仅在当前前台确为已核验、仍存活的任务 Word 时归还前台；目标窗口同时校验 HWND、PID 和线程，关闭、禁用或最小化后不强制打开。用户主动切换应用时更新目标，不固定恢复启动时的窗口。该实现不向 Word 注入 DLL、不禁用 Word 窗口、不切换桌面，也不修改系统前台锁定设置。Windows 拒绝归还请求时记录 `FAILED_REQUESTS`，不因此丢弃转换结果。

`test-ui-experience.ps1 -ShowUi` 观察窗口显示及前台状态；不能仅以异步前台日志判定用户输入是否受到干扰。新增 `test-foreground.ps1` 用两个自建输入框模拟 Unicode `WM_CHAR`、F6 和主动切换窗口，分别统计任务 Word 引起的失焦、用户切到其他应用和字符/快捷键完整性；不发送全局按键，不代替物理键盘或输入法验证。可用 `-BaselineExecutable` 对比旧版，临时输入窗口在测试结束后销毁。

## 测试和隐私

Office 的 OMML 转 MathML 模板会将原生公式中的空格输出为变量节点，MathType 导入后可能出现问号；改成显式间距节点仍会留下不需要的间距标记。正文与额外区域共用的 `ommlMathML` 在导入副本的公式文本中直接删除普通空格、不换行空格及制表换行字符，由 MathType 自动安排数学间距，不改动符号及上下标结构，原文档保持不变。此为明确保留的兼容约定，也适用于 `m:nor` 普通文本，不因其文本类型恢复显式空白；离线适配器回归对此作单独断言。`test-experimental.ps1` 用合成文档覆盖正文行内、行外、表格和页眉，再由实际 MTEF 反向导出检查没有新增问号、竖线或手工间距，且保留数学符号和粗体上下标。

Word 也可能把加减号存为括号对象的 `m:sepChr`，Office 将其输出到 `mfenced/@separators`；MathType 的分隔符文本导入路径会丢失其中的 Unicode 减号。共用 MathML 适配器在顶饰 ASCII 快路径之前，将含加减号的显式分隔符展开为 `<mo>`，其中 U+2212 减号按 `-` 导入；保留括号属性、参数顺序及完整的函数和上下标子树。分隔符去除 XML 空白后按字符顺序使用，不足时重复最后一个；默认逗号、竖线及空分隔符沿用原路径。离线回归覆盖嵌套、多个参数、空括号和脚本归属，不改变 `exp` 与 `e` 指数的原有写法。

公开测试全部使用代码生成的通用样本，不提交 DOCX、PDF、原生偏好文件、原始日志或真实论文。`docs/images/` 仅放行清单中明确列出的合成样本界面及效果图，`docs/benchmarks/` 保存不含本机路径的实测摘要；原始报告和完整文件仍留在本机。每个专项自行准备输入；原生反向样本在本轮由已核验的正向转换生成，不能把历史 JSON 当固定输入。

测试共用入口 `tests/helpers/common.ps1` 显式统一控制台与原生管道为 UTF-8，以匹配 Python `-X utf8` 的 JSON 输出；中文 Windows 的 GBK 控制台否则可能把合法 JSON 解码坏，不能将该类解析失败误判为转换失败。

测试输出只写 `tests/output/`，编译产物只写 `build/`，发布产物只写 `dist/`。私人材料只保存在 `.local/` 和本地隔离资料中，不被公开测试或源码导出读取。

公开文件清单由 `upload-files.txt` 指定。新增文件需同时更新清单与 Git 放行规则；上传前运行 `check-upload.ps1`。Python 测试依赖集中在 `requirements-dev.txt`。

目录整理后应验证干净源码包在另一中文和空格路径下的构建、转换和打包；历史性能数据与旧版本测试结果不作为当前成品验收。

## 本轮验证与后续优化

### 极速模式的执行边界

正式入口为 GUI 极速档或命令行 `--ultra` 配合 `size=14`，与标准／快速共用任务副本、只读原件锁、取消、互斥和最终发布。引擎从私有副本一次读取 DOCX，全部序列化到内存后覆盖该副本，避免 OPC 延迟读取与覆盖冲突。需要本机 MathType，处理 OMML 时使用 Office 的 OMML2MML.XSL，无 Python 或 PowerShell 运行依赖。处理正文普通段落中行内／行外的 LaTeX 与 OMML，支持同段多个公式、两类来源混排和跨连续文本 run 的 LaTeX；保留文字前后缀与各自格式。独立行外公式可选默认右编号，编号仅支持单节单栏、从 1 开始且无旧原生编号的输入。表格、文本框、其他故事、已有 MathType 及复杂编号不处理，也不计为失败。

LaTeX 只识别四种完整定界符 `$...$`、`$$...$$`、`\(...\)`、`\[...\]`，不跨段落、普通域、控件或修订边界拼接。显式行外源码夹在文字间时拆出独立公式段落，共享 `oMathPara` 的多式逐式拆段；每个目标都有独立部件标识。单公式独占段落时按行外处理。普通段落仅含一个公式、手动尾号及空白时，复用 `manualEquationNumber` 识别数字或章-序号，按行外转换，并仅在成功替换后移除普通文本和 Tab。识别并入现有候选扫描，不新增 Word／MathType 调用或全包读写；Tab 仍阻断 LaTeX 拼接。清理不依赖右编号开关，失败保留原式和旧号；正文说明、多公式、域及控件边界不清理，不维护旧号引用。

共用的 `taskCopy` 在复制完成后只解除私有副本继承的文件系统只读属性，原件及其他属性保持。此前只读原件会使极速在完成全部公式导入后无法写回，且失败副本也无法删除；直接调用和监管任务两条路径均在同一处修复，开发 worker 同样使用这一入口。

输入从 DOCX 包直接解析，MathType API 会话在任务内复用；只有存在 OMML 目标时才加载并编译 XSL，纯 LaTeX 不走这一步。`ultra_source.h` 一次确定源节点与文本偏移，在全部成功资产准备完成后倒序替换，避免前面的修改使后面坐标失效；随后按原顺序写入行外编号。

极速未命中资产缓存的 OMML 先调用 `omml_tex.h` 的 `tryOmmlTex`，直接从原始节点生成不带定界符的 ASCII LaTeX，再经现有 `compatibleTex` 适配并补上行内／行外定界符，使用 MathType 的 TeX 接口导入。这条路径不先导入 MathML，也不依赖 MathType 回导 LaTeX。前端支持有明确映射的上下标、横式和线性分式、顶饰、括号、矩阵、无对齐标记的单列公式数组、根式及可伸展积分／求和；不改动源 DOM。字体和结构无法可靠表示时返回 `false`，整式沿用原有 MathML 导入，不输出部分转换内容，也不在导入失败后重试。

实际字体探针确认当前 MathType 的 TeX 字体组合不能同时保留粗体和斜体，因此含 `m:sty="bi"` 标识符的公式整式回退；数字和运算符不因这一样式标记拒绝。小写花体、未知字体及格式、斜分式和 `grow=0` 的大型运算符也使用原路径。根式指数以花括号包裹，避免其中的 `]` 截断 TeX 可选参数。报告的 `OmmlTexImports`、`OmmlMathmlImports` 记录未命中缓存时选用的导入路径次数，`AssetCacheHits` 另列；`OMML_TEX_PREPARE` 单列前端判定及生成耗时，实际厂商调用分别归入 `TEX_IMPORT` 和 `MATHML_IMPORT`。

沿用 MathML 的极速公式仍在共用兼容处理后，复用同一 DOM 去掉无属性、仅含一个子元素的 `mrow`，保留多参数分组、带属性分组及上下标结构；依据为 [MathML 3 的单参数分组等价规则](https://www.w3.org/TR/MathML/chapter3-d.html)。这一分组简化仅由极速开启，标准／快速不启用。共用兼容层本轮同时修复范数括号和关系分隔符：U+2016 的范数括号改成厂商可识别的 `||`，括号参数间的 `/`、`<`、`>`、`≤`、`≥` 等写成显式 `mo`，避免 MathType 漏掉符号；标准、快速及极速的 MathML 路径均使用该修复。最慢 8 次导入日志继续记录序号、正文块、输入长度和实际 TeX／MathML 类型，不逐式回读。

正式构建 `D497DE0C8510BC46B7ADCAC666EE83ECB612A96D8A9A86371EA9F25A8DDDDE5E` 在同一真实 1015 式文档、12 pt、开进度及右编号下耗时 **48.510502 秒**，全部成功，649 个编号；838 次 OMML→LaTeX 导入、142 次 MathML 导入及 35 次资产缓存命中。对比上一版 `0BCB0101…` 的 124.4242028 秒，本轮减少约 **61.0%**。全目标构建与纯 XML 自检通过；这是同机单轮对照，未重跑标准／快速的全量性能及完整回归，Word 验收范围以[实测报告](实测报告.md)为准。证据保存在 `tests/output/omml-tex-20261106/`。

前期输入研究作为历史保留：精简命名空间字符串未确认收益，UTF-8 Bytes 导入被厂商接口拒绝，括号内多参数分组展平未确认整篇提速且存在空括号兼容问题，均未采用。早期“先导入 MathML 再回导 LaTeX”仅用于验证方向，现已由直接前端替代。离线分析仍须注意：lxml 对整个 oMath 文档执行 Office XSL，与生产 MSXML 对选中节点执行处理器会命中不同根模板，研究应以生产输出为准。

`ultra_assets.h` 按本次需要分别准备行内、行外空模板，先写入字号样式并保存为只读复用的 `IStorage`。每个新公式把模板 `CopyTo` 到自己的存储，再用 `OleLoad` 创建独立活动对象，保留一次正常激活及导入；不向上一个活动对象追加内容。`STYLE_WRITE` 从逐式调用缩减为每任务最多两次。相同来源、内容和行内／行外类型的成功资产在当前固定字号任务内缓存；缓存命中省去生成，每个出现位置仍有独立 OLE 部件、关系及对象标识，修改一个公式不会通过共享部件改动其他公式。

厂商生成的 WMF 预览同时提供尺寸和 `MathType/0` 注释中的基线距离。行内与行外都将其从 1/16 pt 转成 Word 使用的半磅 `w:position`，不按图片高度猜测，分式右编号也对齐公式基线；行内段落属性保持，行外公式按来源的显示方式排版。对象 run、Tab、编号及行外排版 XML 模板每任务按需解析一次，逐式克隆并写入实际标识、尺寸、基线及编号缓存。编号仍为可编辑的 MathType 原生域结构，不调用 Word 更新。

主流程不启动 Word，不核验结果，不进行逐式回滚或重试。逐式进度共用 `StageProgress`，最多每 150 ms 更新；耗时明细单列包读取／写入、OLE 创建／加载／激活／关闭、样式写入、TeX／MathML 导入、OLE 存储及预览导出。开发用 `ultra-equation-worker --verify` 才启动 Word 检查样本，固定样本断言位于 `tests/native/test_ultra_native.h`，不编入 GUI。以上记录实现路径；扩展后的功能与速度结论以最终构建的定向检查和大样本记录为准。

候选筛选只累计极速范围内的 LaTeX 与 OMML，表格等范围外内容保留，不因保留它们而报告部分完成。报告及界面按“正文块 N”（正文顶层段落、表格等容器的原始顺序）定位，不冒充 Word 段号。编号的九个 XML 节点合并一次解析后按顺序导入，取消逐节点重复创建解析器；服务断连直接终止，不逐式重复失败。
